Kloomie API

Read and write your contacts, tasks, visits, invoices and Projects records from other apps, and hear the moment something happens.

Keys

A team owner or admin makes an API key in Settings → Connections → Connect other apps. It's shown once. Send it with every request:

Authorization: Bearer col_…

The base address is your Kloomie server followed by /api/v1, for example https://app.kloomie.com/api/v1. A key reaches the team's contacts, tasks, visits and invoices, and every project that isn't private. A key can be read and write or read only. Deleting it in Settings stops it at once. Contacts and invoices need a key made by someone who is still an owner or admin.

curl https://app.kloomie.com/api/v1/me -H "Authorization: Bearer $COLUMN_KEY"
{"team":"Premier","key":"Zapier","write":true,"role":"owner","events":["record.created", …]}
GET/membersThe team: [{"id", "name", "role"}]. Anywhere a person goes in, send their id or name.

Lists

Contacts, tasks and invoices list the same way: {"data": [ … ], "next_cursor": …}, oldest change first. Page with ?limit= (up to 500) and ?cursor=, and ask for only what changed with ?updated_since= (see Syncing). For the latest few, newest first (what a polling trigger wants), use ?order=newest&limit=25. Money is in dollars, dates look like 2026-11-30, times of day like "09:30", and moments are ISO times.

Contacts

The team's people: customers, leads, anyone you call or email.

GET/contactsContacts. Find someone with ?email= or ?phone= (however it's written), or filter by ?stage= or ?tag=.
POST/contactsAdd one. With "match_existing": true, someone already here with the same email or phone gets their empty details filled in instead, and the answer has "matched": true. Good for web forms and lead sources.
GET/contacts/{id}One contact.
PATCH/contacts/{id}Change some details.
DELETE/contacts/{id}Delete one. People synced in from Google Contacts can't be deleted here, since they'd come back.
GET PUT/contacts/external/{external_id}Find, or upsert, by your system's id.
curl -X POST https://app.kloomie.com/api/v1/contacts -H "Authorization: Bearer $COLUMN_KEY" -H "Content-Type: application/json" \
  -d '{"name": "Dana Ruiz", "email": "dana@example.com", "phone": "555-010-0100", "source": "Website", "tags": ["lead"], "match_existing": true}'
→ { "id": "c9…", "external_id": null, "name": "Dana Ruiz", "company": "", "email": "dana@example.com", "phone": "555-010-0100",
    "address": "", "city": "", "source": "Website", "stage": "", "note": "", "tags": ["lead"], "do_not_contact": false,
    "assigned_to": null, "synced_from": null, "created_at": "…", "updated_at": "…" }

A contact's details: name, company, email, phone, address, city, source, stage, note, tags (a list, or one string with commas), do_not_contact and external_id. A contact synced from somewhere else (synced_from) keeps the details that place owns, like its name and email.

Projects & fields

Syncing

To keep another system in step, remember the time of your last sync and ask only for what changed since, page by page:

GET /projects/$PROJECT/deals/records?updated_since=2026-11-02T00:00:00Z&limit=500
→ { "records": [ … ], "next_cursor": "1793400000000.q8Lx…" }
GET /projects/$PROJECT/deals/records?updated_since=2026-11-02T00:00:00Z&limit=500&cursor=1793400000000.q8Lx…
→ { "records": [ … ], "next_cursor": null }

Going the other way, write with PUT …/external/{your id}: running it twice can't make a duplicate. Deletions arrive as webhooks (below).

Errors & limits

Errors are JSON, {"error": "What went wrong, in words"}, with the usual status: 400 bad value, 401 missing or wrong key, 403 read-only key, 404 not found, 409 that external_id is already used, 429 too many requests.

Each key can make 300 requests a minute. A team can keep 50,000 records.

A record event looks like this. The others are the same without project and list:

{
  "id": "evt_9fQ…",
  "type": "record.updated",            // any event above (or "ping" from Send a test)
  "created_at": "2026-11-02T17:05:00.000Z",
  "by": "Sam",                         // who made the change; an API key shows as "Zapier (API)"
  "project": { "id": "Hk2…", "name": "Sales" },
  "list": "deals",
  "data": { …the record, as above… }
}

Headers: X-Kloomie-Event, X-Kloomie-Delivery (the event id, for ignoring repeats) and X-Kloomie-Signature: t=<seconds>,v1=<signature>.

Checking the signature

The signature is an HMAC-SHA256 of t + "." + the raw body, made with the webhook's secret (shown once when it's made). Check it, and reject old timestamps:

// Node
import crypto from 'node:crypto';
function fromKloomie(rawBody, header, secret) {
  const { t, v1 } = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(t)) > 300) return false; // older than 5 minutes
  const want = crypto.createHmac('sha256', secret).update(`${t}.${rawBody}`).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(want), Buffer.from(v1));
}
# Python
import hmac, hashlib, time
def from_kloomie(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    if abs(time.time() - int(parts["t"])) > 300:
        return False
    want = hmac.new(secret.encode(), f'{parts["t"]}.'.encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(want, parts["v1"])

Answer with any 2xx within 10 seconds. Anything else is tried again after 30 seconds, 2 minutes and 8 minutes. After 20 failures in a row the webhook pauses; turn it back on in Settings. The last 20 deliveries show there too. Webhook addresses must be public: private network addresses are refused. Records in private projects are never sent.

Subscribing to webhooks from an app

An app that wants to hear about things (like Zapier's instant triggers) can add and remove its own webhooks with its key, without anyone visiting Settings. They show in Settings too, marked as added by an app.

POST/webhooks{"url": "https://…", "events": ["contact.created"]}, or "event" for one. Returns the webhook and its secret, shown this once. Leave out events for all of them.
GET/webhooksThe webhooks this key added.
DELETE/webhooks/{id}Remove one this key added.

Using it with Zapier or Make

Zapier: Kloomie has its own Zapier app. Add Kloomie to your Zapier account, then sign in with an API key. It has instant triggers for everything above (contacts, tasks, visits, invoices, payments, files, signatures), actions to add or update contacts, add and complete tasks, book visits and record payments, and searches for contacts and invoices.

Make, or anything else: Use their webhook trigger with the address they give you as a Kloomie webhook, and their HTTP action with your API key in the Authorization header to add or update things. match_existing on contacts, PUT by external_id, and a payment's reference all keep repeated runs from making duplicates.
