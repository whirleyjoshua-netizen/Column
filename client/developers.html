Column API

Read and write the records in your Projects (contacts, companies, deals, anything you track) from other apps, and hear the moment they change.

Keys

A team owner makes an API key in Settings → Connections → Connect other apps. It's shown once. Send it with every request:

Authorization: Bearer col_…

The base address is your Column server followed by /api/v1, for example https://column.example.com/api/v1. A key reaches every project that isn't private. A key can be read and write or read only. Deleting it in Settings stops it at once.

curl https://column.example.com/api/v1/me -H "Authorization: Bearer $COLUMN_KEY"
{"team":"Premier","key":"Zapier","write":true}

Projects & fields

A project has lists (Contacts, Companies, Deals…), and each list has fields. Every list and field has a key, like contacts or close_date, that never changes when someone renames it in Column. Use keys in your code.

GET/projectsEvery project the key reaches, with its lists and fields.
GET/projects/{project_id}One project's lists and fields.

Records

GET/projects/{project_id}/{list}/recordsRecords, oldest change first. ?limit= (up to 500), ?cursor=, ?updated_since=
POST/projects/{project_id}/{list}/recordsAdd one. Body: {"fields": {…}, "external_id": "optional"}
GET/projects/{project_id}/{list}/records/{id}One record.
PATCH/projects/{project_id}/{list}/records/{id}Change some fields. Fields you leave out stay as they are; null clears one.
DELETE/projects/{project_id}/{list}/records/{id}Delete it (and links to it).
GET/projects/{project_id}/{list}/records/external/{external_id}Find a record by your system's id.
PUT/projects/{project_id}/{list}/records/external/{external_id}Upsert: update the record with that id, or add it. The safest way to sync.
curl -X PUT https://column.example.com/api/v1/projects/$PROJECT/contacts/records/external/hubspot-4411 \
  -H "Authorization: Bearer $COLUMN_KEY" -H "Content-Type: application/json" \
  -d '{"fields": {"name": "Maria Lopez", "email": "maria@desertauto.com", "stage": "Qualified", "owner": "Sam"}}'

Syncing

To keep another system in step, remember the time of your last sync and ask only for what changed since, page by page:

GET /projects/$PROJECT/deals/records?updated_since=2026-11-02T00:00:00Z&limit=500
→ { "records": [ … ], "next_cursor": "1793400000000.q8Lx…" }
GET /projects/$PROJECT/deals/records?updated_since=2026-11-02T00:00:00Z&limit=500&cursor=1793400000000.q8Lx…
→ { "records": [ … ], "next_cursor": null }

Going the other way, write with PUT …/external/{your id}: running it twice can't make a duplicate. Deletions arrive as webhooks (below).

Errors & limits

Errors are JSON, {"error": "What went wrong, in words"}, with the usual status: 400 bad value, 401 missing or wrong key, 403 read-only key, 404 not found, 409 that external_id is already used, 429 too many requests.

Each key can make 300 requests a minute. A team can keep 50,000 records.

Webhooks

A team owner adds a webhook in Settings with an https:// address, for every project or one. Column sends a POST when a record is added, changed or deleted:

{
  "id": "evt_9fQ…",
  "type": "record.updated",            // record.created, record.updated, record.deleted (or "ping" from Send a test)
  "created_at": "2026-11-02T17:05:00.000Z",
  "by": "Sam",                         // who made the change; an API key shows as "Zapier (API)"
  "project": { "id": "Hk2…", "name": "Sales" },
  "list": "deals",
  "data": { …the record, as above… }
}

Headers: X-Column-Event, X-Column-Delivery (the event id, for ignoring repeats) and X-Column-Signature: t=<seconds>,v1=<signature>.

Checking the signature

The signature is an HMAC-SHA256 of t + "." + the raw body, made with the webhook's secret (shown once when it's made). Check it, and reject old timestamps:

// Node
import crypto from 'node:crypto';
function fromColumn(rawBody, header, secret) {
  const { t, v1 } = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(t)) > 300) return false; // older than 5 minutes
  const want = crypto.createHmac('sha256', secret).update(`${t}.${rawBody}`).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(want), Buffer.from(v1));
}
# Python
import hmac, hashlib, time
def from_column(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    if abs(time.time() - int(parts["t"])) > 300:
        return False
    want = hmac.new(secret.encode(), f'{parts["t"]}.'.encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(want, parts["v1"])

Answer with any 2xx within 10 seconds. Anything else is tried again after 30 seconds, 2 minutes and 8 minutes. After 20 failures in a row the webhook pauses; turn it back on in Settings. The last 20 deliveries show there too. Webhook addresses must be public: private network addresses are refused. Records in private projects are never sent.

Using it with Zapier or Make

Use their webhook trigger with the address they give you as a Column webhook, and their HTTP action with your API key in the Authorization header to add or update records (PUT by external_id keeps runs from making duplicates).
